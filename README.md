# cooolinho.de

Personal portfolio website with a terminal-styled interface, built with Vite and SCSS. Canonical URL: https://cooolinho.de/

## Requirements

- Node.js 22 (see `.nvmrc`) and npm
- Optional: [GitHub CLI](https://cli.github.com) (`gh`), logged in as `cooolinho` – only needed to update the GitHub stats

## Getting started

```bash
npm install
npm run dev
```

Open the URL shown by Vite (default: `http://localhost:5173`).

## Commands

| Command           | Description                                            |
| ----------------- | ------------------------------------------------------ |
| `npm run dev`     | Start the dev server                                   |
| `npm run build`   | Build the site into `/dist` (incl. `sitemap.xml`)      |
| `npm run preview` | Preview the production build (serves `/dist`)          |
| `npm run stats`   | Refresh `src/data/github-stats.json` (see below)       |
| `npm run release` | Tag and push the next version, triggering a deploy     |
| `npm run deploy`  | Upload `/dist` via SFTP (used by CI, see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)) |

## Deployment

Deployment is automatic: pushing a version tag (`npm run release`) builds and
uploads the site via SFTP, and a daily job redeploys the latest tag after
refreshing the GitHub stats. See **[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)**
for the full setup (SFTP credentials, GitHub secrets, versioning scheme) and
day-to-day usage.

Manual deploy without CI, if ever needed:

```bash
npm run build
npm run deploy   # requires .env.deploy — see docs/DEPLOYMENT.md
```

The host must redirect `http://` and `www.cooolinho.de` with **301** to
`https://cooolinho.de/` – this must match the canonical URL.

## SEO

### Meta tags & structured data

Everything lives in the `<head>` of `index.html`:

- `title`, `description`, `robots`, canonical URL, favicons
- Open Graph and X (Twitter) card tags incl. `og-image.png`
- JSON-LD `@graph` with `WebSite`, `ProfilePage` and `Person`

When content changes, keep these in sync with the visible page (e.g. `description`, `jobTitle`, `worksFor`, `knowsAbout`). If you replace an image, keep its dimensions or update the related values (`og:image:width`/`og:image:height`, `width`/`height` of `Person.image`).

### robots.txt

`public/robots.txt` is a static file. Vite copies it unchanged to `dist/robots.txt`.

```
User-agent: *
Allow: /

Sitemap: https://cooolinho.de/sitemap.xml
```

- Allows all crawlers to access the whole site and points them to the sitemap.
- To block a path, add e.g. `Disallow: /intern/` below `Allow: /`.
- `robots.txt` only controls crawling, not indexing. To keep a page out of Google, use `<meta name="robots" content="noindex">` on that page instead (and do **not** block it in `robots.txt`, otherwise Google never sees the `noindex`).

### sitemap.xml

There is **no** `sitemap.xml` in the repository – it is generated on every `npm run build` by the `sitemap()` plugin in `vite.config.js` and written to `dist/sitemap.xml`.

How the plugin works:

1. After the build (`closeBundle`) it scans `/dist` for all `.html` files.
2. Pages containing `<meta name="robots" content="noindex">` are skipped.
3. File paths are turned into URLs based on `SITE_URL`:

   | Built file            | URL                                    |
   | --------------------- | -------------------------------------- |
   | `index.html`          | `https://cooolinho.de/`                |
   | `projekte/index.html` | `https://cooolinho.de/projekte/`       |
   | `lebenslauf.html`     | `https://cooolinho.de/lebenslauf.html` |

4. `<lastmod>` is the date of the last commit that touched the source HTML file (`git log -1 --format=%cs`). Consequences:
   - Uncommitted changes are not reflected – commit before building.
   - Without Git (e.g. a plain file copy) `<lastmod>` is omitted.
   - In CI, check out the full history (e.g. `fetch-depth: 0` with `actions/checkout`); with a shallow clone every page would get the date of the latest commit.

Check the result:

```bash
npm run build
```

```bash
cat dist/sitemap.xml
```

The sitemap is not available in the dev server – use `npm run preview` and open `http://localhost:4173/sitemap.xml`.

### Adding a new page

1. Create the page as `<name>/index.html` (gives a clean URL like `/projekte/`):

   ```
   projekte/
   └── index.html
   ```

2. Register all pages as build inputs in `vite.config.js` (Vite 8: `rolldownOptions`, `rollupOptions` is deprecated). Without this, Vite only builds `index.html`:

   ```js
   import { join, relative, resolve } from 'node:path';

   // …

   build: {
     outDir: 'dist',
     assetsDir: 'assets',
     sourcemap: false,
     rolldownOptions: {
       input: {
         main: resolve(import.meta.dirname, 'index.html'),
         projekte: resolve(import.meta.dirname, 'projekte/index.html'),
       },
     },
   },
   ```

3. Give the page its own `<head>` SEO data: `title`, `description`, `<link rel="canonical" href="https://cooolinho.de/projekte/">`, `og:url` and matching Open Graph tags. Favicons can be copied from `index.html`.
4. Commit, then run `npm run build` – the page appears in `dist/sitemap.xml` automatically. Nothing needs to be changed in `robots.txt`.
5. After deployment: request indexing of the new URL in Google Search Console (URL inspection).

### Changing the domain

The domain appears in several places – update all of them:

- `SITE_URL` in `vite.config.js`
- `Sitemap:` line in `public/robots.txt`
- `index.html`: canonical link, `og:url`, `og:image` and all `@id`/`url` values in the JSON-LD

### Google Search Console

1. Add a domain property for `cooolinho.de` (verification via DNS TXT record).
2. Submit `https://cooolinho.de/sitemap.xml` under *Sitemaps*.
3. Use *URL inspection* to check that Google uses `https://cooolinho.de/` as canonical URL.

Useful checks after deployment: [Rich Results Test](https://search.google.com/test/rich-results), [Schema Markup Validator](https://validator.schema.org/), [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/).

## GitHub stats

The `gh stats cooolinho` section and the project counters in the focus cards are rendered from `src/data/github-stats.json`. If the file is missing, the page shows a placeholder.

Every deploy (release or daily) refreshes this file automatically before building – see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). It is **not** committed to the repo; the copy checked in is only a fallback for local dev.

To update it locally, either use the Claude Code skill (requires `gh auth login` as `cooolinho`):

```
/update-github-infos
```

or run the underlying script directly: `npm run stats` (add `-- --dry-run` to preview without writing the file). Featured repos, language settings and focus detection are configured in `.claude/skills/update-github-infos/config.json`; details in the skill's `SKILL.md`.
